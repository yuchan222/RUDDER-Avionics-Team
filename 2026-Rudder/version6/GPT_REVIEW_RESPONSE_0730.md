## 코드 설계 방향

이번 대응에서 지킨 원칙:

1. **새 서브시스템을 만들기보다, 이미 있는 변수·플래그를 완성해서 쓴다.**
   예: `g_baselineOk`는 이미 있었는데 GCS 표시용으로만 쓰이고 있었음 — 새 상태를 추가하지 않고 이 값을 실제 판정 로직에 연결하는 것으로 끝냄.
2. **이미 존재하는 안전망이 있으면, 그 위에 새 계층을 쌓지 않는다.**
   예: 기준압이 나빠도 가속도 기반 발사감지와 10초 보조사출 타이머가 이미 백업 역할을 하고 있음 — 이 사실을 전제로 최소 비용으로만 보강함.
3. **팀이 의도적으로 선택한 단순화는, 외부 리뷰가 반대해도 그 이유가 여전히 유효하면 유지한다.**
   예: IMU WHO_AM_I 미검사(클론칩 허용), 명령 ACK 프로토콜 미도입.
4. **코드가 짧아지거나 로직이 단순해지는 방향의 지적은 적극 수용한다.**
   예: 명령 다수결을 "4개 중 2개 일치(이중 for문)" → "4개 완전 일치(비교 3개)"로 바꿔 오히려 코드가 줄어듦.
5. **안전에 직접 영향 없는 개선(로그 편의성, 표시 문구 정확도 등)은 대회 임박 시점에서 우선순위를 낮춘다.**

## 반영하지 않은 항목과 이유

**이미 있는 안전망으로 충분하다고 판단**
- P0-G3 / P1-G1 (링크 신선도 추적 서브시스템 — 케이블 분리 감지, 패킷 나이 기반 버튼 비활성화 등): 수신율(pkt/s) 지표가 끊기면 곧바로 0으로 떨어져 사실상 같은 역할을 하고 있음. 새 상태 필드·스레드 상태 추적 시스템을 통째로 만드는 건 지금 시점에 과한 투자.

**우리 위협모델에 안 맞음**
- P1-G3 (패킷 구조/범위 필드별 검증 강화): CRC16이 이미 대부분의 손상을 걸러냄. 이 지적은 "패킷을 조작하는 공격자"를 가정한 것에 가까운데, 저희는 잡음(노이즈) 환경이지 적대적 환경이 아님.

**기존 설계와 상충**
- P1-S3 (IMU WHO_AM_I 값 화이트리스트 요구): `Sensors.cpp` 상단에 명시된 대로, 클론 칩도 동작하게 하려고 의도적으로 WHO_AM_I 판정을 안 하는 것. 이 지적을 받아들이면 오히려 기존 설계 취지와 정반대가 됨.

**관측된 적 없는 문제에 대한 선제적 인프라**
- P0-F4 전체 (실행시간 전부 계측 + 오버런 카운터를 텔레메트리 필드로 추가): 온도 오버샘플링 낮추는 것 외의 나머지(최악실행시간 로깅, 오버런 카운터 신설)는 실측 없이 인프라부터 짓는 셈. 최종 배선·SD카드로 하드웨어 시험할 때 실제 문제가 보이면 그때 대응.
- P0-F5 (10초 보조사출의 "완전 독립성" 확보): 물리적으로 MCU를 하나 더 둬야 하는 하드웨어 재설계 영역. `CHANGES.md`에 "동일 MCU 내 보조조건"이라고 표현만 정정해둔 상태 유지 — 추가 코드 조치 없음.
- P0-2 (서보 전원 유지시간 최종값): MOSFET 실물이 아직 없어 값 자체를 정할 수 없음. 구조(P0-F1)는 오늘 고쳤고, `SERVO_RECMD_MS`/hold 시간 같은 실제 값은 실물시험 후 확정.

**회수 후 데이터 분석 편의성 문제 — 비행 안전과 무관**
- P1-L1 (SD 쓰기/sync 실패를 실시간 상태비트에 반영)
- P1-L2 (사전할당 8MB 파일을 실제 크기로 truncate)
- P1-L3 (착륙 전환 시점을 SD 로그 마지막 줄에 기록)
- P1-L4 (LOG00001~99999 전부 소진 시 덮어쓰기 방지)

**상태비트로 이미 어느 정도 커버됨**
- P1-S1 (INA219 NaN/범위 미검증): 배터리 전압·전류 표시용이고 발사/사출 로직에 안 쓰임.
- P1-S2 (IMU 실패 시 GCS가 이전 가속도값을 계속 표시): IMU 상태점은 이미 빨갛게 뜨고, 펌웨어의 발사감지 로직도 이미 `imuOk` 체크로 막혀있어 실제 오탐 위험은 낮음.
- P1-S5 (BMP 기준압/실시간 압력의 물리범위 하드바운드): 이번에 고친 P0-F2(기준압 불량 시 고도경로 차단)·P0-F3(연속성 리셋)로 핵심 위험은 상당 부분 커버됨.

**별도 일정으로 진행 예정**
- P1-S6 (IMU 축·부호 고정): 최종 장착 방향 실물 확인이 필요해서 내일(2026-07-31) 학교에서 진행.
