# version5 수정 내역 (2026-07-29)

version4를 기준선으로 유지한 채, 아래 내용을 반영해 새로 만든 버전입니다.

## 1. 비상사출 자동재전송 버그 (오늘 발견한 첫 문제)

**증상**: 로켓 재연결하자마자 낙하→착륙으로 자동 전환됨
**원인**: 이전 테스트의 `eject_phase=2`(자동 재전송 중) 상태가 GCS 세션에 남아있다가, 재연결하는 순간 밀린 `FORCE_EJECT`가 나감
**수정**:
- `_reset_flight_data()`(연결 버튼 누를 때마다 실행)에 `eject_phase`/`ff_confirm` 초기화 추가
- 재전송 자체에 **30초 시간제한** 추가 — 확인 안 되면 자동 중단

**비용**: 낮음 — 기존 함수에 몇 줄 추가, 새 상수(`MAX_RETRY_S`) 1개

## 2. GCS 그래프 잔상 버그

**증상**: 재연결하면 그래프가 0초부터 시작은 하는데 이전 그래프가 안 지워짐
**원인**: Plotly 차트 위젯 key가 고정돼서 Streamlit이 "기존 위젯 업데이트"로 처리
**수정**: 재연결마다 증가하는 `chart_epoch` 카운터를 key에 포함시켜 매번 새 위젯으로 인식하게 함

**비용**: 매우 낮음 — 변수 1개 + 기존 3곳에 반영

## 3. GPT 기술검토서(P0 7개 + P1 5개) 대응

| 항목 | 변경 내용 | 비용 |
|---|---|---|
| **P0-1** | `FORCE_EJECT`를 대기·착륙에서 거부 (준비·비행·낙하만 허용) | 낮음 — if문 1개 |
| **P0-3** | 기준압 수집 실패해도 진입은 허용, 대신 GCS에 새 상태점("기준압") 표시 | 낮음 — 상태비트 1개 재활용, 새 필드 없음 |
| **P0-4** | 최고고도 갱신에 "3회 연속 확인" 조건 추가 (단일 스파이크 방지) | 낮음 — 카운터 변수 1개 |
| **P0-5** | 자동 착륙판정 로직 전체 삭제 → `FORCE_LAND` 수동 전환만 남김 | **오히려 코드 감소** — 함수 하나(`checkLanding`) + 상수 5개 삭제 |
| P0-2 | (보류) 서보 전원 유지시간 관리 | MOSFET 실물 없어서 값 자체를 못 정함 |
| P0-6 | (부분 대응) | 핵심 위험(비상사출 오인식)은 이미 `eject_state` 기반으로 해결됨. 검토서가 제안한 "명령별 sequence+ACK 전체 프로토콜"은 안 함 |
| P0-7 | (보류) 독립 백업 아님 | 진짜 해결은 MCU 하나 더 놓는 하드웨어 재설계. 코드로 할 수 있는 게 없어서, 보고서 문구("독립 백업"이라는 과장된 표현 정정)만 권고 |
| **P1-1** | BMP 상태점이 최신 읽기 결과를 반영하도록 수정 (기존엔 초기화 성공 이후 고정) | 낮음 — 변수 1개(`s_bmpInited`) 분리 |
| **P1-2** | `-1` sentinel → `ALT_INVALID`(INT32_MIN)로 교체 | 낮음 — 상수 1개, 5개 지점 치환 |
| **P1-3** | 센서읽기→상태기계→패킷화 순서로 재배치 (사건 발생 샘플의 로그 밀림 방지) | 매우 낮음 — 4줄 위치만 이동 |
| **P1-5** | SD 로그 파일번호 카운터 타입버그(`uint16_t`→`uint32_t`) 수정 | 매우 낮음 — 타입 하나 |
| P1-4 | (내일 예정) IMU 축·부호 고정 | 실물 장착방향 확인이 필요해서 당일 불가 |

### 전체 비용 평가

복잡도가 늘어난 부분은 P0-1, P0-3, P0-4, P1-1 정도이며, 전부 기존 함수에 몇 줄씩 추가하는 수준이었다. P0-5는 함수와 상수를 통째로 삭제해 오히려 코드가 줄었다. 새로운 추상화 계층·클래스·파일 구조를 추가하지 않아 하루치 작업으로는 복잡도 증가를 잘 억제했다고 판단.

### 나머지(P0-2, P0-6 전체 프로토콜, P0-7)를 보류한 공통 이유

전부 "코드만으로는 해결이 안 되는" 항목이다.
- **P0-2**: 실측(MOSFET 하드웨어)이 있어야 정할 수 있는 값
- **P0-6 전체 프로토콜**: 핵심 위험은 이미 더 간단한 방법(eject_state)으로 막아놔서, 복잡한 재설계를 추가할 필요성이 낮다고 판단
- **P0-7**: 물리적으로 MCU를 하나 더 놓아야 하는 하드웨어 재설계라 코드 영역 밖의 문제
