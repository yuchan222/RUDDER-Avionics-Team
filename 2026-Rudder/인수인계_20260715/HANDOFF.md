## 1. 현재 상태 요약 (여기까지 됐고, 여기서 막힘)

### ✅ 검증 완료 (확실히 동작함)
| 항목 | 내용 |
|---|---|
| SiK 텔레메트리 ↔ GCS | 아두이노 → 무선(433MHz) → 지상국 전체 체인 검증 성공. GCS에서 실시간 그래프/타임라인/CSV 로깅 확인 |
| SD카드 모듈 | init + 파일 쓰기 정상 (`SD_BMP_Test`로 확인) |
| GCS 소프트웨어 | 가상 시뮬레이션 모드 + 실제 COM 포트 수신 모두 동작. 비상사출 명령 프로토콜 버그도 수정 완료 |

### ⚠️ 문제 진행 중 (인수인계 시점의 핵심 과제)
**MPU-6050, INA219, 레벨시프터가 I2C로 인식되지 않음.**

증상: 대부분 무응답 → 수십 초에 한 번 주소가 잡혔다가 바로 끊김 (간헐 접촉 패턴).
MPU는 잠깐 초기화에 성공해 값이 나온 적도 있으나 물리적으로 불가능한 쓰레기 값 + 매번 끊김.

**지금까지 배제된 원인** (이미 해봤으니 다시 안 해도 됨):
- ❌ 아두이노 보드 문제 → 다른 UNO 보드로 교체해도 동일
- ❌ USB 케이블/전원 → 케이블 전부 교체해도 동일
- ❌ R4 풀업 부족 → 레벨시프터(풀업 내장) 경유해도 동일
- ❌ 배선 위치 실수 → 간헐적으로 주소가 잡히는 것 자체가 배선 위치는 맞다는 증거

**남은 용의자 2개**:
1. **모듈 납땜 불량(냉납)** — 세 모듈이 같은 시기에 납땜됨. 실제로 MPU GND 납땜이 선 무게만으로 떨어진 사례 있음
2. **점퍼선 자체 불량** — 테스트 내내 같은 점퍼선 세트를 사용했음

**칩 자체는 정상으로 추정** — 간헐적으로 주소 응답 + 데이터 송신이 확인됨 (죽은 칩은 아예 조용함).

### ▶ 다음에 할 일 (이 순서대로)
1. **새 점퍼선 세트로 교체 후 재테스트** (2분, 제일 빠른 확인)
2. **멀티미터 도통(연속성) 테스트** — 모듈 핀 납땜부 ↔ 점퍼선 반대쪽 끝을 재서 어디서 끊기는지 확정. 삐- 소리 나면 통함, 조용하면 그 지점이 범인
3. 납땜 문제로 확정되면 → **플럭스 바르고 전 핀 재납땜** (인두를 핀+패드에 2~3초 충분히 예열 → 실납 투입 → 반짝이는 원뿔 모양 확인)
4. 재납땜 후 테스트 스케치로 재검증 (아래 3번 섹션)
5. 3개 모듈 다 통과하면 → 전체 통합 회로 → `version2` 펌웨어 풀 테스트

## 2. 개발 환경 셋업 (처음 하는 사람용)

### 2-1. Arduino IDE 설치
1. https://www.arduino.cc/en/software 에서 IDE 2.x 설치
2. 보드 지원 추가: **Tools → Board → Boards Manager** → "UNO R4" 검색 → **Arduino UNO R4 Boards** 설치
3. 라이브러리 설치: **Tools → Manage Libraries**에서 아래 5개 검색해 설치 (의존성 물어보면 "Install all")
   - `Adafruit MPU6050`
   - `Adafruit BMP3XX`
   - `Adafruit INA219`
   - `SdFat` (Bill Greiman)
   - `Servo` (기본 포함일 수 있음)

### 2-2. 업로드/시리얼 모니터 사용법 + 함정 모음
- 스케치 열기: 폴더 안의 `.ino` 파일 더블클릭 (폴더명과 ino 파일명이 같아야 열림 — 이 스냅샷은 이미 맞춰져 있음)
- 보드 선택: Tools → Board → **Arduino UNO R4 Minima**
- **⚠️ 포트 선택 함정 (우리가 실제로 헤맨 것)**: SiK 라디오가 꽂혀 있으면 COM 포트가 2개 이상 보임.
  - 아두이노 = "Arduino UNO R4 Minima"라고 이름 붙은 포트
  - SiK = "USB Serial Port" (여기 선택하면 업로드 실패 + 시리얼 모니터 아무것도 안 나옴)
- 시리얼 모니터: 돋보기 아이콘, **baud rate 반드시 115200**
- 출력이 안 보이면: ① 포트 다시 확인 ② 아두이노 리셋 버튼 한 번 누르고 2초 대기 (모든 테스트 스케치에 부팅 후 3초 시리얼 대기가 들어있어서 리셋하면 처음부터 다시 나옴)
- **LED 켜져 있다고 전원 정상이 아님!** GND가 끊겨도 신호선을 타고 전류가 새서 LED가 켜지는 "유령 전원" 현상이 있음 (실제로 겪음). 전원 확인은 멀티미터로 VCC-GND 전압을 재는 것만 믿을 것

## 3. 테스트 스케치 사용법 (이 폴더 안에 전부 있음)

모든 스케치는 "한 번 업로드 → 시리얼 모니터만 보면 됨" 방식. 센서를 꽂거나 빼면 몇 초 안에 상태가 자동 갱신됨.

| 폴더 | 용도 | 성공 기준 |
|---|---|---|
| `I2C_Module_Check` | MPU/BMP/INA 3종 동시 감시 (2초마다 O/X 표) | 연결한 모듈에 `[O] 인식됨` |
| `MPU_Test` | MPU 단독 진단 + 실시간 가속도/자이로 출력 | `[O] 초기화 성공` 후 **끊김 없이** 값 출력, 기울이면 값 변화, 가만두면 Z≈9.8 |
| `INA219_Test` | INA 단독 진단 + 전압/전류 출력 | `[O] 초기화 성공` (전류값은 VIN+/−에 부하 없으면 0 근처가 정상) |
| `LevelShifter_Test` | 시프터 관통 테스트 (센서를 시프터 건너편에 연결) | 건너편 센서 주소가 `[O]`로 뜨면 시프터 정상 |
| `SD_BMP_Test` | SD 쓰기 + BMP388 진단 | `[OK] SD write` / `[OK] BMP388` |
| `Actuator_Test` | 서보(D9) + LED(74HC595) + 부저(D8) 반복 구동 | 서보 0↔90도 왕복, LED 점멸, 삑 소리 |
| `Fake_Telemetry_Test` | 센서 없이 가짜 비행데이터를 SiK로 송신 (GCS 테스트용) | GCS에 그래프 올라옴 |

### 공통 배선 (I2C 센서: MPU, BMP, INA)
| 센서 핀 | 아두이노 |
|---|---|
| VCC | 5V (또는 3.3V) |
| GND | GND |
| SDA | A4 |
| SCL | A5 |

- I2C는 여러 센서를 같은 A4/A5에 병렬로 물려도 됨 (주소가 달라서 충돌 없음: MPU=0x68, BMP=0x76, INA=0x40)
- BMP388은 I2C 전용 4핀(VCC/GND/SCL/SDA) 쪽을 사용. 그래도 인식 안 되면 왼쪽 줄의 `CS` 핀을 VCC에 연결해볼 것

### SiK 라디오 배선 (공중측)
| SiK 핀 | 아두이노 |
|---|---|
| 5V (빨간선) | 5V |
| GND | GND |
| TX | **D0 (RX)** ← 교차! |
| RX | **D1 (TX)** ← 교차! |
| RTS/CTS | 사용 안 함 |

- **TX/RX는 반드시 교차**: 내 입(TX)을 상대 귀(RX)에. 라벨끼리 맞추면 통신 안 됨 (실제로 겪음)
- 지상측 SiK는 USB로 노트북에 꽂기만 하면 됨
- 양쪽 녹색 LED가 **깜빡임 없이 점등** = 페어링 성공. 빨간 LED 깜빡임 = 데이터 흐르는 중

## 4. GCS (지상국) 실행법

```
cd 2026-Rudder/GCS
pip install -r requirements.txt   (최초 1회)
python -m streamlit run gcs.py
```

- 브라우저에 http://localhost:8501 자동으로 열림
- 기본은 **가상 시뮬레이션 모드** (아두이노 없이도 화면 동작 확인 가능)
- 실제 수신: 사이드바 → 포트 선택에서 🔌 표시된 SiK 포트 선택 → "연결"
- **SiK를 뽑았다 다시 꽂으면 "연결" 버튼을 다시 눌러야 함** (포트 핸들이 죽어서 데이터가 안 들어옴 — 실제로 겪음)
- 아두이노를 리셋하면 그래프가 자동으로 초기화됨 (재부팅 감지 기능 내장)
- 수신 데이터는 `GCS/logs/`에 CSV로 자동 저장

## 5. version2 (비행 펌웨어) 관련 주의사항

- `version2/` = 실제 비행 코드. 모드 구조: 0 대기 → 1 Armed → 2 비행 → 3 사출완료 → 4 착지
- **⚠️ 중요**: 현재 `Config.h`에 `TEST_SKIP_IMU_CHECK`가 켜져 있음 — MPU 없이도 Mode 2 진입을 허용하는 **지상 테스트 전용** 스위치. **실제 비행 전 반드시 이 줄을 주석 처리할 것** (부팅 시 시리얼에 경고가 뜨니 잊기 어려움)
- Mode 0에서는 1초마다 `[MODE0] standby status=0x..` 하트비트가 출력됨. status 비트: 0x01=BMP, 0x02=IMU, 0x04=SD, 0x08=INA (예: 0x0F = 전부 정상)
- GCS의 비상사출 버튼은 로켓이 **Mode 1(Armed) 이상**일 때만 동작함 (안전장치)
